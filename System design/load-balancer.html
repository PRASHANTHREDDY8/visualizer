Load Balancer

Distributes incoming network traffic across multiple servers to ensure high availability, reliability, and performance at scale.

Networking High Availability Scalability Layer 4 & 7

◇ Architecture Overview

□ Component Breakdown

⬡ Layer 4 Load Balancer

Distributes traffic based on IP and TCP/UDP port without inspecting packet contents.
Technology AWS NLB, HAProxy (TCP mode), IPVS
Throughput Millions of packets/sec, sub-ms latency
Scaling Horizontal via DNS or ECMP routing

⬡ Layer 7 Load Balancer

Inspects HTTP headers, URLs, and cookies to make intelligent routing decisions.
Technology NGINX, Envoy, AWS ALB, Traefik
Features Path routing, SSL termination, compression
Scaling Horizontal behind L4 LB

● Health Checker

Continuously monitors backend server health and removes unhealthy nodes from the pool.
Interval Every 5-30 seconds per target
Checks TCP connect, HTTP 200, custom endpoints
Threshold 2-3 failures before removal

■ Backend Servers

Application instances that process the actual business logic for incoming requests.
Scaling Auto-scale based on CPU/RPS metrics
Stateless No local session state — store in Redis
Deploy Rolling updates with graceful drain

◆ Session Persistence

Ensures a client's requests consistently reach the same server when needed.
Methods Cookie-based, IP hash, header-based
Trade-off Sticky sessions reduce distribution evenness
Best for WebSocket, shopping carts, uploads

◈ SSL/TLS Termination

Offloads encryption/decryption from backend servers, reducing their CPU load.
Location At L7 load balancer (most common)
Benefit Centralized cert management, backend HTTP
Security Re-encrypt to backends in zero-trust envs

⬆ Horizontal Scaling

Add more LB instances behind DNS or BGP anycast. L4 balancers in front of L7 fleet. Each L7 instance handles ~50K connections. Scale linearly by adding nodes.

🔄 Active-Passive vs Active-Active

Active-passive: standby LB takes over on failure (simpler, some failover delay). Active-active: all LBs serve traffic simultaneously (better utilization, needs state sync).

⚠ Single Point of Failure

The LB itself must be redundant. Solutions: floating IP with keepalived/VRRP, cloud-managed LBs (AWS ELB), DNS failover across regions, or anycast BGP routing.

🔒 SSL Termination Trade-off

Terminating at LB simplifies backends but means unencrypted internal traffic. For compliance, use mutual TLS between LB and backends (adds ~2ms latency).

📍 Global vs Regional

Global LB (GeoDNS/Anycast) routes to nearest region. Regional LB distributes within a data center. Two tiers are standard for multinational services.

💔 Connection Draining

When removing a server, allow existing requests to complete (30-60s drain period). New requests go elsewhere immediately. Critical for zero-downtime deploys.
