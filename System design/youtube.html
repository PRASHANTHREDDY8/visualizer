Component Breakdown

Technology choices, responsibilities, and scaling strategies for each component.

CDN (Content Delivery Network)

Serves video segments from edge nodes closest to viewers

Google Global Cache Akamai/Cloudflare Edge PoPs
Caches ~90% of watch traffic. Popular videos pre-warmed. Long-tail videos fetched on demand from origin. Uses consistent hashing for segment placement.

Video Upload Service

Accepts chunked uploads, validates content, triggers processing

gRPC Pub/Sub Resumable Upload
Supports resumable uploads for large files. Deduplicates identical content via perceptual hashing. Publishes "video_uploaded" event to start transcoding pipeline.

Transcoding Pipeline

Encodes raw video into multiple resolutions, bitrates, and codecs

DAG Scheduler FFmpeg Workers Task Queue
DAG-based pipeline: split into segments, transcode in parallel, merge. Outputs: 360p/480p/720p/1080p/4K in H.264 + VP9 + AV1. Generates thumbnails, subtitles.

Video Streaming Service

Generates manifests, handles adaptive bitrate switching

HLS DASH Manifest Generator
Creates .m3u8 (HLS) and .mpd (DASH) manifests listing all quality levels. Client downloads segments and switches quality based on bandwidth. DRM enforcement via Widevine/FairPlay.

Metadata Service

Manages video info, channels, playlists, comments

Vitess (Sharded MySQL) Redis Spanner
Video metadata sharded by video_id. Channel data denormalized for fast reads. Comments use Bigtable for high-write throughput. Hot metadata cached in Redis with 30s TTL.

Recommendation Engine

Personalized video suggestions and search ranking

TensorFlow Serving Feature Store Embedding Index
Two-tower model: candidate generation (1000s) + ranking (top 20). Uses watch history, subscriptions, and co-watch signals. Search uses inverted index + semantic embeddings.

Analytics & View Counting

Real-time view counts, watch time, engagement tracking

Kafka Apache Flink Bigtable
Client sends heartbeats every 10s during playback. Kafka ingests events, Flink aggregates in windows. View count eventually consistent — batched writes prevent hotspot on viral videos.

Message Queue / Event Bus

Async communication between services

Kafka Google Pub/Sub Dead Letter Queue
Topics: video_uploaded, transcode_complete, view_event, comment_posted. Enables loose coupling. Dead letter queues catch failures for retry. Partitioned by video_id for ordering.

Use Cases & When to Apply

Video-on-Demand Platforms

Netflix, Disney+, educational platforms. Same transcoding + CDN pattern. Vary by catalog size and recommendation importance.

User-Generated Content

TikTok, Instagram Reels. Similar upload/transcode pipeline but shorter content, higher upload volume, more aggressive recommendation.

Live Streaming Extensions

YouTube Live, Twitch. Adds real-time ingest (RTMP), lower-latency transcoding, and live edge distribution (LL-HLS).

Enterprise Video (Training/Meetings)

Zoom recordings, corporate LMS. Smaller scale, private CDN, stricter access controls, simpler recommendation.

Don't Use For: Real-Time Conferencing

Video calls need sub-200ms latency. ABR streaming adds too much delay. Use WebRTC/SFU architecture instead.

Don't Use For: Small File Delivery

For short clips (<30s), the transcoding pipeline overhead isn't justified. Simple object storage + CDN suffices.

Key Trade-offs

Storage CostStreaming Quality

More transcoded variants = better UX but exponential storage. YouTube stores ~5-8 variants per video.

ConsistencyAvailability

View counts are eventually consistent (seconds delay acceptable). Video availability is prioritized over exact count accuracy.

LatencyThroughput

Recommendations are precomputed (high throughput batch) but served from cache (low latency reads).

CostFreshness

CDN caches reduce origin load but content staleness requires careful TTL management and cache invalidation.

Failure Scenarios

CDN Node Failure

DNS routes to next-closest PoP. Users see brief rebuffer (~1-2s). No data loss.

Transcoding Worker Crash

Segment is re-queued for another worker. Increases processing time but no video loss (raw stored).

Metadata DB Shard Down

Redis cache serves reads for TTL duration. Writes queue in Kafka. Partial degradation for affected videos.

Recommendation Service Down

Fallback to popularity-based suggestions. UX degrades (less personalized) but site stays functional.
